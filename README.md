# Nutrients Backend

Веб-сервис на NestJS для управления нутриентами. Предметная область — витамины, минералы и другие полезные вещества. Реализует REST API для SPA и мобильных приложений.

## Стек технологий

- NestJS — фреймворк для бэкенда
- TypeORM — ORM для работы с БД
- PostgreSQL — база данных
- MinIO — S3-хранилище для изображений и видео
- Docker Compose — развёртывание инфраструктуры

## Структура БД

### Таблица `users`

Хранит пользователей системы.

- `id` — первичный ключ, автоинкремент
- `username` — уникальный логин (varchar 100)
- `password` — пароль (varchar 255), в ЛР4 будет хешироваться через bcrypt
- `role` — роль пользователя (varchar 50), по умолчанию «создатель»

### Таблица `nutrients`

Хранит нутриенты (витамины, минералы и т.д.).

- `id` — первичный ключ, автоинкремент
- `name` — название нутриента (varchar 100)
- `dailyNorm` — дневная норма (float, nullable)
- `unit` — единица измерения: мг, г, мкг (varchar 20, nullable)
- `description` — описание (text, nullable)
- `status` — статус: «черновик», «опубликован», «удален» (varchar 20, по умолчанию «черновик»)
- `imageKey` — ключ изображения в MinIO (varchar 255, по умолчанию пусто)
- `videoKey` — ключ видео в MinIO (varchar 255, по умолчанию пусто)
- `createdAt` — дата создания (timestamp, автоматически)
- `formedAt` — дата публикации (timestamp, nullable)
- `creatorId` — внешний ключ на `users.id` (int)

Связь: `nutrients.creatorId` → `users.id` (многие к одному, onDelete RESTRICT).

### Таблица `likes`

Хранит лайки (связь многие-ко-многим между пользователями и нутриентами).

- `id` — первичный ключ, автоинкремент
- `userId` — внешний ключ на `users.id` (int)
- `nutrientId` — внешний ключ на `nutrients.id` (int)

Связи: `likes.userId` → `users.id`, `likes.nutrientId` → `nutrients.id` (onDelete RESTRICT).

## HTTP методы

Базовый URL: `http://localhost:3000/api`

### Домен nutrients

**GET /nutrients** — получить список опубликованных нутриентов с фильтрацией. Query-параметры: `search` (поиск по названию), `minNorm` (минимальная дневная норма), `maxNorm` (максимальная дневная норма). Возвращает массив нутриентов.

**GET /nutrients/feed** — получить первую опубликованную карточку для ленты. Возвращает один нутриент.

**GET /nutrients/feed/:id?next=true** — получить следующую карточку после указанного id. Если после id ничего нет — возвращает первую (зацикливание). Возвращает один нутриент.

**GET /nutrients/draft** — получить черновик текущего пользователя. У пользователя не может быть больше одного черновика. Возвращает нутриент или null.

**GET /nutrients/:id** — получить один нутриент по id. Возвращает нутриент или 404, если не найден.

**POST /nutrients** — создать черновик. Принимает multipart/form-data с полями `name`, `description`, `dailyNorm`, `unit` и файлами `image`, `video`. Файлы загружаются в MinIO, в БД сохраняются их ключи. Возвращает созданный нутриент.

**PUT /nutrients/:id/publish** — опубликовать черновик. Меняет статус на «опубликован» и устанавливает `formedAt`. Тело запроса не требуется. Возвращает обновлённый нутриент.

**DELETE /nutrients/:id** — мягкое удаление. Меняет статус на «удален». Возвращает 204 No Content.

**POST /nutrients/:id/like** — поставить или убрать лайк. Принимает JSON с полем `value`: 1 — поставить лайк, 0 — убрать. Возвращает 204 No Content.

### Домен users

**POST /users/register** — зарегистрировать нового пользователя. Принимает JSON с полями `username` (минимум 3 символа) и `password` (минимум 6 символов). Возвращает данные пользователя без пароля.

**POST /users/auth** — аутентификация. Принимает JSON с полями `username` и `password`. Возвращает данные пользователя без пароля. В ЛР3 это заглушка, в ЛР4 будет JWT/сессия.

**POST /users/deauth** — деавторизация. Заглушка для ЛР4. Возвращает 204 No Content.
